# M4.2 finite source-domain nested evaluation

Recorded before executing M4.2 nested outer-domain results. The original final ACS, hospital, bank and 2025 College target outcomes have already been inspected and remain excluded from this study. This is a finite source-development experiment, not a new untouched confirmation.

For ACS use seven source states and household IDs; for hospital use four source admission codes and patient IDs, excluding patients spanning codes; for bank use the first four contiguous fit blocks and forward-only outer validation on blocks 2 and 3. The first bank block is subdivided in time for inner router cross-fitting; later source blocks supply selection and calibration. Other families use stable entity-hash partitions within each *outer training* domain for inner fit, selection, probability calibration, and threshold calibration. All base experts and preprocessing are re-fit inside every outer fold. Inner router predictions come only from domain-held-out or forward-only fits within outer training rows. The outer domain is excluded from inner model fitting, selection, calibration and hyperparameter decisions.

Five fixed experts and existing configurations are used. No new expert search. Static expert is chosen by inner selection Brier. The uniform and inverse-selection-Brier ensembles use the same five fitted experts. The source-calibrated fixed expert uses sigmoid calibration on the separate probability-calibration partition. The existing metadata router fits five Ridge(alpha=100) squared-error models on 12 probability-derived metadata values; a simplified router uses each expert probability plus inter-expert standard deviation, also Ridge(alpha=100). These hyperparameters are frozen: no outer-domain tuning or grid search. The decision to retain either for confirmation is based only on nested source results and recorded before any new confirmation labels are accessed.

For each policy report Brier, log loss, AUROC/AUPRC, 10-bin ECE, fitting and inference time, and confidence- and disagreement-ranked selective risk. Source threshold-calibration rows set a nominal 80% acceptance cutoff. Separately, a batch-transductive threshold may use only unlabeled outer scores to achieve approximately 80% acceptance; it is not an online policy and never reads outer labels for thresholding. Compare accepted error at actual coverage; a policy below 80% is infeasible for the selective objective. Rows are never treated as independent deployment environments; summarize by outer domain and family. No test-domain-informed hyperparameter change is allowed.

The fresh confirmation candidate is UCI Online Shoppers Purchasing Intention (dataset 468, CC BY 4.0), with month-based natural shift and the UCI `Revenue` label. It is a separate fourth family. Details, methods and success criteria will be committed in a separate preregistration **after** source evaluation and **before** opening shopper labels. If provenance, release timing, or month support fails feasibility checks, stop confirmation rather than recycle an inspected target.
